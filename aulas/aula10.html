🎨 Material UI (MUI)

O que é Material UI?

Biblioteca de componentes React baseada no Material Design do Google. Usada por empresas como Netflix, Uber, Amazon.

Vantagens:

  • ✅ Componentes prontos e profissionais
  • ✅ Acessibilidade built-in (ARIA, navegação por teclado)
  • ✅ Sistema de temas consistente
  • ✅ Responsivo por padrão
  • ✅ Documentação excelente

Instalação:

npm install @mui/material @emotion/react @emotion/styled
npm install @mui/icons-material

Configuração do Tema:

// src/main.tsx
import { ThemeProvider, createTheme } from '@mui/material/styles';
import CssBaseline from '@mui/material/CssBaseline';

const theme = createTheme({
  palette: {
    primary: { main: '#007acc' },
    secondary: { main: '#ff4081' },
  },
});

ReactDOM.createRoot(document.getElementById('root')!).render(
  <ThemeProvider theme={theme}>
    <CssBaseline />
    <App />
  </ThemeProvider>
);

Exemplo: Botão com Loading

❌ Antes (CSS Modules)

<button

🚀 React Hook Form

O que é React Hook Form?

Biblioteca para gerenciar formulários no React com performance e facilidade.

Vantagens:

  • ✅ Performance: sem re-renders desnecessários
  • ✅ API simples e intuitiva
  • ✅ Integração com validadores (Zod, Yup, etc.)
  • ✅ Tipagem forte com TypeScript

Instalação:

npm install react-hook-form @hookform/resolvers zod

API Básica:

import { useForm } from 'react-hook-form';

const {
  register,      // Registra inputs
  handleSubmit,  // Handler do submit
  formState: { errors, isSubmitting },
  reset,         // Limpa o formulário
} = useForm();

🔍 Zod: Validação de Schemas

O que é Zod?

Biblioteca para validação de schemas com TypeScript. Define contratos de dados de forma declarativa.

Exemplo: Schema de Beneficiário

// src/schemas/beneficiarioSchema.ts
import { z } from 'zod';

export const beneficiarioSchema = z.object({
  nome: z.string()
    .min(3, 'Nome deve ter pelo menos 3 caracteres')
    .max(150, 'Nome deve ter no máximo 150 caracteres'),
  
  cpf: z.string()
    .regex(/^\d{11}$/, 'CPF deve ter 11 dígitos'),
  
  telefone: z.string()
    .regex(/^\d{10,11}$/, 'Telefone inválido')
    .optional(),
  
  endereco: z.string()
    .max(255, 'Endereço deve ter no máximo 255 caracteres')
    .optional(),
});

// TypeScript infere o tipo automaticamente
export type BeneficiarioFormData = z.infer<typeof beneficiarioSchema>;
💡 Vantagem do Zod: O tipo BeneficiarioFormData é gerado automaticamente a partir do schema. Se você mudar o schema, o TypeScript avisa onde precisa atualizar o código.

🔗 Integração: React Hook Form + Zod + MUI

Formulário Completo:

import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { TextField, Button, Box, Alert } from '@mui/material';
import { beneficiarioSchema, BeneficiarioFormData } from '../schemas/beneficiarioSchema';
import api from '../services/api';

export function BeneficiarioForm() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
    reset,
  } = useForm<BeneficiarioFormData>({
    resolver: zodResolver(beneficiarioSchema),
  });

  const onSubmit = async (data: BeneficiarioFormData) => {
    try {
      await api.post('/beneficiarios', data);
      reset();
      alert('Beneficiário criado com sucesso!');
    } catch (error) {
      alert('Erro ao criar beneficiário');
    }
  };

  return (
    <Box component="form" onSubmit={handleSubmit(onSubmit)} sx={{ maxWidth: 600, mx: 'auto', p: 3 }}>
      <TextField
        label="Nome"
        {...register('nome')}
        error={!!errors.nome}
        helperText={errors.nome?.message}
        fullWidth
        margin="normal"
      />
      
      <TextField
        label="CPF"
        {...register('cpf')}
        error={!!errors.cpf}
        helperText={errors.cpf?.message}
        fullWidth
        margin="normal"
      />
      
      <TextField
        label="Telefone"
        {...register('telefone')}
        error={!!errors.telefone}
        helperText={errors.telefone?.message}
        fullWidth
        margin="normal"
      />
      
      <TextField
        label="Endereço"
        {...register('endereco')}
        error={!!errors.endereco}
        helperText={errors.endereco?.message}
        fullWidth
        margin="normal"
      />
      
      <Button 
        type="submit" 
        variant="contained" 
        disabled={isSubmitting}
        sx={{ mt: 2 }}
      >
        {isSubmitting ? 'Cadastrando...' : 'Cadastrar'}
      </Button>
    </Box>
  );
}
✅ Benefícios desta abordagem:
  • Validação automática: Zod valida antes de enviar para a API
  • Tipagem forte: TypeScript garante que os dados estão corretos
  • Performance: React Hook Form não re-renderiza o formulário inteiro
  • UX profissional: MUI mostra erros de forma clara e acessível

♿ Acessibilidade (WCAG 2.1)

Por que Acessibilidade?

  • 🌍 1.3 bilhão de pessoas com deficiência no mundo
  • 🇧🇷 45 milhões de pessoas com deficiência no Brasil
  • ⚖️ Lei Brasileira de Inclusção (LBI) exige acessibilidade digital

Princípios WCAG (POUR):

PrincípioSignificadoExemplo
Perceptível Informação apresentada de formas múltiplas Texto alternativo em imagens
Operável Interface usável com teclado, mouse, voz Todos os botões acessíveis por Tab
Compreensível Conteúdo claro e previsível Mensagens de erro claras
Robusto Funciona com tecnologias assistivas Compatível com leitores de tela

🎯 Acessibilidade no Material UI

O que o MUI já faz por você:

  • ✅ Roles ARIA automáticos
  • ✅ Navegação por teclado
  • ✅ Contraste de cores adequado
  • ✅ Labels associados a inputs

O que você precisa fazer:

  • ✅ Usar aria-label quando necessário
  • ✅ Garantir foco visível
  • ✅ Testar com leitor de tela

Exemplo: Tornando Acessível

❌ Inacessível

<div onClick={handleClick}>
  <EditIcon />
</div>

✅ Acessível

import { IconButton } from '@mui/material';
import { Edit } from '@mui/icons-material';

<IconButton 
  onClick={handleClick}
  aria-label="Editar beneficiário"
>
  <Edit />
</IconButton>

🧪 Teste de Usabilidade Cruzado

Como funciona:

  1. Dupla A cria a interface (30 min)
  2. Dupla B testa sem olhar o código (15 min)
  3. Dupla B preenche checklist de usabilidade
  4. Dupla A recebe feedback e itera (15 min)

Checklist de Usabilidade:

CritérioComo Testar
Eficiência Conseguir cadastrar um beneficiário em < 30s
Clareza de Erros Mensagens de erro são claras e úteis
Acessibilidade por Teclado Interface funciona sem mouse (só Tab e Enter)
Contraste Contraste de cores é adequado (ferramenta: WebAIM)
Responsividade Layout funciona em mobile (redimensionar janela)
💡 Dica: Use a extensão Lighthouse do Chrome para auditar acessibilidade automaticamente. Ela gera um relatório com pontuação e sugestões de melhoria.
