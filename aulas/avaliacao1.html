🏢 Cenário de Negócio

A ONG SocialConnect recebe diariamente doações físicas (alimentos, roupas, itens de higiene). Atualmente, o controle é feito em planilhas, o que gera problemas como:

  • Estoque negativo (mais saídas que entradas).
  • Falta de alerta quando um produto está abaixo do estoque mínimo.
  • Dificuldade em saber quais produtos precisam ser solicitados aos doadores.

Sua missão é implementar o módulo de Produtos da API, permitindo o cadastro, consulta, atualização e remoção de produtos do estoque, com regras de negócio rigorosas.

📦 Como Entregar

Passo a passo:

  1. Crie uma nova branch(avalicao1) no seu repositório público(socialconnect) GitHub pessoal.
  2. Implemente todos os requisitos no módulo produtos.
  3. Rode mvn clean compile e garanta que o projeto compila sem erros.
  4. Verifique o Swagger em http://localhost:8080/swagger-ui.html.
  5. Commits descritivos: Use Conventional Commits (ex: feat(produtos): implementa CRUD).
  6. Push para o seu repositório pessoal.
  7. Envie o link do repositório via atividade no Teams.
💡 Importante: O repositório deve ser público para facilitar a correção.
⚠️ Prazo: Entregas após 23:59 do dia da aula terão desconto de 10% por hora de atraso.

1️⃣ Entidade e Persistência (15% da nota)

Requisitos:

  • Criar a Entity Produto.java com os campos abaixo.

  • Padrão obrigatório: chave primária com prefixo id_ (ex: id_produto).

2️⃣ DTOs e Validações (15% da nota)

Requisitos:

  • Criar ProdutoRequestDTO (entrada) e ProdutoResponseDTO (saída) como record.
  • Aplicar Bean Validation (@NotBlank, @Size, @Min, etc.).
  • Criar pelo menos uma validação customizada (sugestão: @EstoqueNaoNegativo ou similar).

Exemplo de ProdutoRequestDTO:

public record ProdutoRequestDTO(
    @NotBlank(message = "{produto.nome.obrigatorio}")
    @Size(max = 150)
    String nome,

    @NotNull(message = "{produto.categoria.obrigatoria}")
    CategoriaProduto categoria,

    @Min(value = 0, message = "{produto.estoque.minimo}")
    Integer estoqueAtual,

    @Min(value = 0)
    Integer estoqueMinimo,

    @NotBlank
    @Size(max = 20)
    String unidadeMedida
) {}

3️⃣ Service e Regras de Negócio (20% da nota)

Regras Obrigatórias:

  1. Estoque não negativo: O sistema DEVE rejeitar qualquer operação que resulte em estoqueAtual < 0. Retornar 422 Unprocessable Entity com Problem Details.
  2. Alerta de estoque baixo: O ProdutoResponseDTO DEVE incluir um campo booleano estoqueBaixo que é true quando estoqueAtual < estoqueMinimo.
  3. Nome único: Não permitir cadastrar produto com nome já existente. Retornar 409 Conflict.

Métodos obrigatórios do Service:

public interface ProdutoService {
    Page<ProdutoResponseDTO> listar(String nome, CategoriaProduto categoria, Pageable pageable);
    ProdutoResponseDTO buscarPorId(Long id);
    ProdutoResponseDTO criar(ProdutoRequestDTO dto);
    ProdutoResponseDTO atualizar(Long id, ProdutoRequestDTO dto);
    void deletar(Long id);
}

4️⃣ Controller e Semântica HTTP (20% da nota)

Endpoints Obrigatórios:

GET /api/v1/produtos?page=0&size=10&sort=nome,asc&categoria=ALIMENTO

Retorna lista paginada. Filtros opcionais: nome (parcial) e categoria.

GET /api/v1/produtos/{id_produto}

Retorna 200 OK com o produto, ou 404 Not Found com Problem Details.

POST /api/v1/produtos

Cria produto. Retorna 201 Created com cabeçalho Location. Possíveis erros: 400, 409, 422.

PUT /api/v1/produtos/{id_produto}

Atualização total. Retorna 200 OK. Possíveis erros: 400, 404, 409, 422.

DELETE /api/v1/produtos/{id_produto}

Remove produto. Retorna 204 No Content ou 404 Not Found.

Exemplo de Resposta (ProdutoResponseDTO):

{
  "idProduto": 1,
  "nome": "Arroz 5kg",
  "categoria": "ALIMENTO",
  "estoqueAtual": 3,
  "estoqueMinimo": 10,
  "unidadeMedida": "unidade",
  "dataCadastro": "2026-09-18",
  "estoqueBaixo": true  // ← 3 < 10
}

5️⃣ Swagger/OpenAPI (15% da nota)

🏆 Sem Swagger = -30% na nota final.

Requisitos:

  • Todos os endpoints devem estar documentados com @Tag, @Operation, @ApiResponse.
  • DTOs devem ter exemplos via @Schema(example = "...").
  • O Swagger UI deve estar acessível em http://localhost:8080/swagger-ui.html.
  • Deve ser possível testar todos os endpoints pelo Swagger.

6️⃣ Qualidade do Código (15% da nota)

Critérios avaliados:

  • Organização: Estrutura de pacotes clara (controller, service, repository, dto, model).
  • Injeção de dependência: Via construtor com campos final (sem @Autowired em campos).
  • Nomenclatura: Variáveis e métodos com nomes descritivos em camelCase.
  • Commits: Mensagens descritivas seguindo Conventional Commits.
  • README: Documentação básica do projeto (como rodar, endpoints principais).

🤖 Política de Uso de IA

Conforme o arquivo AI_USAGE.md do repositório base, o uso de IA é permitido e incentivado, desde que:

  1. Transparência total: Você deve documentar no README ou em um arquivo AI_USAGE.md como usou a IA (quais prompts, quais ferramentas).
  2. Compreensão: Você deve ser capaz de explicar cada linha do código entregue.
